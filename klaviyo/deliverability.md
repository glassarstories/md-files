# Доставлюваність (Deliverability)

> Якщо листи не доходять до Inbox, усе інше (тексти, оффери, флоу) не має значення. Цей файл — довідник по DNS, прогріву, вимогах поштових провайдерів і гігієні бази. Перевіряти раз на квартал і після будь-яких змін DNS/домену.

## Вимоги Gmail / Yahoo / Microsoft для масових відправників

З 2024 року великі поштові провайдери вимагають від відправників маркетингових листів:

| Вимога | Як виконуємо | Статус |
|---|---|---|
| SPF і DKIM на домені відправника | Брендований домен відправки в Klaviyo + записи кореневого домену | [ ] |
| DMARC-запис (мінімум `p=none`) | TXT `_dmarc.butterflarium.com` | [ ] |
| Вирівнювання (alignment) домену From з SPF або DKIM | Брендований домен відправки на тому ж домені, що й From | [ ] |
| One-click unsubscribe (`List-Unsubscribe` + `List-Unsubscribe-Post`) | Klaviyo додає автоматично | [ ] |
| Обробка відписки протягом 2 днів | Klaviyo — миттєво | ✅ |
| Spam complaint rate < **0.3%** (краще < 0.1%) | Моніторинг у Klaviyo + Google Postmaster Tools | [ ] |
| Валідні прямі/зворотні DNS, TLS | Забезпечує Klaviyo | ✅ |

## DNS-записи

> Точні значення CNAME/TXT видає Klaviyo в Settings → Domains. Сюди вписуємо фактично додані записи для довідки.

| Тип | Хост | Значення | Призначення | Додано | Статус |
|---|---|---|---|---|---|
| CNAME | [send] | [видає Klaviyo] | Брендований домен відправки | | |
| CNAME / TXT | [kl._domainkey.send …] | [видає Klaviyo] | DKIM | | |
| TXT | `@` | `v=spf1 include:_spf.google.com ~all` (приклад для Google Workspace) | SPF кореневого домену | | |
| TXT | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc@butterflarium.com` | DMARC (старт з моніторингу) | | |

**Важливо:**
- На домені може бути лише **один** SPF-запис — нові `include:` додавати в існуючий, а не створювати другий.
- DMARC починати з `p=none`, через 4–8 тижнів чистих звітів → `p=quarantine`, далі можливо `p=reject`.
- DNS-реєстратор/хостинг домену: [Shopify Domains / GoDaddy / Cloudflare / ін.]

## Прогрів (warm-up) нового домену / акаунта

Новий домен без репутації не можна одразу "вистрілити" на всю базу. Принцип: спочатку найактивніші контакти, поступово розширювати.

| Тиждень | Кому відправляємо | Орієнтовний обсяг за відправку |
|---|---|---|
| 1 | Engaged 30 днів (відкривали/клікали/купували нещодавно) + флоу | до кількох сотень |
| 2 | Engaged 60 днів | ×1.5–2 від попереднього |
| 3 | Engaged 90 днів | ×1.5–2 |
| 4+ | Engaged 120–180 днів | за умови чистих метрик |

Флоу (Welcome, Abandoned Checkout) можна вмикати одразу — вони йдуть невеликими обсягами на "теплих" людей і допомагають набирати репутацію.

**Стоп-сигнали під час прогріву** (зупинити розширення, повернутись на крок назад):
- bounce rate > 2%
- spam complaint rate > 0.1%
- open rate різко впав (особливо на Gmail-адресах)

## Гігієна бази

- **Не купувати і не імпортувати бази без згоди.** Ніколи.
- **Sunset-флоу** для неактивних (див. [`flows.md`](flows.md)) — після нього непрореагувавших переводимо в suppressed.
- **Engaged-сегменти** для кампаній: регулярні розсилки — на Engaged 90 (або 120/180 залежно від частоти), не на весь список.
- Hard bounce — Klaviyo автоматично suppress; перевіряти долю раз на місяць.
- Перевіряти імпорт на ролеві адреси (`info@`, `admin@`) і одноразові домени.
- **Apple Mail Privacy Protection** завищує open rate → для визначення "залученості" спиратися насамперед на кліки, покупки, активність на сайті; відкриття — допоміжний сигнал.

## Моніторинг

| Інструмент | Що дивитись | Частота |
|---|---|---|
| Klaviyo → Deliverability (Hub/Score) | Bounce, spam, unsubscribe по кампаніях/провайдерах | щотижня |
| Google Postmaster Tools | Репутація домену в Gmail, spam rate | щотижня (після підключення) |
| DMARC-звіти (rua) | Хто відправляє від імені домену, чи проходить alignment | щомісяця |
| Ручний seed-тест | Inbox / Promotions / Spam на Gmail, Outlook, Yahoo | при зміні шаблону/домену |
