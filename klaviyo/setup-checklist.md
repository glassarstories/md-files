# Чекліст налаштування Klaviyo з нуля

> Проходити зверху вниз. Відмічати `[x]` та дату. Не переходити до флоу і розсилок, поки не закрито блоки 1–3 — інакше листи підуть зі спамовою репутацією або без даних для персоналізації.

## 1. Акаунт і базові налаштування

- [ ] Створити акаунт Klaviyo на робочий email бренду (не особистий)
- [ ] Увімкнути 2FA для всіх користувачів
- [ ] Settings → Account → **Organization**: назва бренду, сайт, індустрія, фізична адреса (обов'язково для футера за CAN-SPAM)
- [ ] Встановити **таймзону** та **валюту** (USD) — змінити таймзону пізніше складно, вона впливає на всі звіти й розклад
- [ ] Settings → **Email** → sender name, sender email, reply-to
- [ ] Додати користувачів з мінімально потрібними ролями (див. [`account-overview.md`](account-overview.md))
- [ ] Зберегти Private API key у менеджері паролів (не в репозиторії)

## 2. Домен відправки та доставлюваність

> Детально — у [`deliverability.md`](deliverability.md).

- [ ] Створити адресу відправки на власному домені (`hello@butterflarium.com`), **не** gmail/yahoo
- [ ] Налаштувати **брендований домен відправки** (Settings → Domains → Sending domain, напр. `send.butterflarium.com`) і додати DNS-записи, які видасть Klaviyo
- [ ] Переконатись, що на кореневому домені є **SPF** і **DKIM** для поштового сервісу, з якого пишемо вручну (Google Workspace тощо)
- [ ] Додати **DMARC**-запис (мінімум `p=none` з адресою для звітів) — обов'язкова вимога Gmail/Yahoo для масових відправників
- [ ] Дочекатись статусу **Verified** у Klaviyo
- [ ] (Опційно) брендований домен для посилань/трекінгу, якщо доступно на тарифі
- [ ] Перевірити, що one-click unsubscribe працює (Klaviyo додає `List-Unsubscribe` автоматично)

## 3. Інтеграція з Shopify

- [ ] Встановити офіційний **Klaviyo: Email Marketing & SMS** app з Shopify App Store і підключити до акаунта
- [ ] У налаштуваннях інтеграції увімкнути: синхронізацію клієнтів, замовлень, каталогу; **sync email subscribers** у потрібний список
- [ ] Увімкнути **onsite tracking**: Online Store → Themes → Customize → App embeds → Klaviyo ✅
- [ ] Перевірити, що в Analytics → Metrics з'явились події: `Active on Site`, `Viewed Product`, `Added to Cart`, `Started Checkout`, `Placed Order`, `Ordered Product`, `Fulfilled Order`, `Cancelled Order`, `Refunded Order`
- [ ] Shopify → Settings → Checkout: увімкнути чекбокс згоди на email-маркетинг (з чітким текстом, не попередньо відміченим, якщо орієнтуємось на строгі стандарти)
- [ ] Перевірити, що профілі зі Shopify, які **не давали згоду**, не потрапили до маркетингового списку (лише транзакційні/непідписані)
- [ ] Тестове замовлення → переконатись, що `Placed Order` з'явився в профілі з правильною сумою й товарами

## 4. Списки та базові сегменти

> Детально — у [`lists-segments.md`](lists-segments.md).

- [ ] Створити основний список `Newsletter` (або використати дефолтний) — **один** головний маркетинговий список
- [ ] Налаштувати double opt-in або single opt-in (рішення та причину записати в [`lists-segments.md`](lists-segments.md))
- [ ] Створити базові сегменти: Engaged 30/60/90/180, Покупці, Ніколи не купували, Повторні покупці, Неактивні (для Sunset), Suppressed
- [ ] Імпорт старої бази (якщо є) — лише контакти з **підтвердженою згодою**; позначити джерело імпорту в властивості профілю

## 5. Бренд і шаблони

> Детально — у [`content-guidelines.md`](content-guidelines.md).

- [ ] Settings → **Brand library**: логотип, кольори, шрифти (web-safe fallback), соцмережі
- [ ] Створити **майстер-шаблон**: хедер з логотипом, блок-герой, футер з адресою, посиланням відписки, manage preferences, соцмережами
- [ ] Шаблон адаптивний — перевірити на мобільному (більшість відкриттів з телефону)
- [ ] Налаштувати сторінку відписки / **preference page** у брендових кольорах
- [ ] Підготувати бібліотеку фото товарів (стиснуті, ширина ~1200px, alt-тексти)

## 6. Форми підписки

> Детально — у [`signup-forms.md`](signup-forms.md).

- [ ] Popup для нових відвідувачів (desktop + mobile окремо) з оффером
- [ ] Embedded форма у футері сайту
- [ ] Повідомлення про згоду + посилання на Privacy Policy у формі
- [ ] Форма додає в список `Newsletter` і тригерить Welcome-флоу
- [ ] Перевірити показ форми на мобільному (не перекриває весь екран одразу — штрафи Google за intrusive interstitials)

## 7. Флоу (автоматизації) — у порядку пріоритету

> Детально — у [`flows.md`](flows.md). Кожен флоу спочатку в статусі **Draft → Manual** (ручний тест), потім **Live**.

- [ ] Welcome Series
- [ ] Abandoned Checkout
- [ ] Browse Abandonment
- [ ] Added to Cart (Abandoned Cart)
- [ ] Post-Purchase (перша покупка / повторна)
- [ ] Review Request
- [ ] Win-back
- [ ] Sunset (неактивні)
- [ ] Перевірити, що транзакційні листи Shopify (підтвердження замовлення, доставка) залишаються в Shopify — Klaviyo їх не дублює

## 8. Тестування перед запуском

- [ ] Preview & test на реальних адресах: Gmail, Outlook, Apple Mail (iPhone)
- [ ] Усі посилання ведуть куди треба, UTM-мітки на місці
- [ ] Динамічні блоки (товари з кошика, ім'я) мають fallback, якщо даних немає (`{{ first_name|default:'there' }}`)
- [ ] Знижкові коди — унікальні (Klaviyo ↔ Shopify) і реально працюють на чекауті
- [ ] Перевірити спам-скор/рендеринг (Inbox preview або сторонній тест)
- [ ] Smart Sending увімкнено в маркетингових флоу (щоб людина не отримала 3 листи за день)

## 9. Перша кампанія та прогрів

- [ ] Перші розсилки — лише на **найактивніший** сегмент (Engaged 30/60 днів), не на всю базу
- [ ] Поступово розширювати аудиторію за графіком прогріву в [`deliverability.md`](deliverability.md)
- [ ] Записати результати в [`campaign-log.md`](campaign-log.md)

## 10. Після запуску — регулярні перевірки

- [ ] Щотижня: результати кампаній і флоу, spam complaint rate, bounce rate
- [ ] Щомісяця: аудит флоу (чи не зламались фільтри/коди), ріст бази, частка email у виручці
- [ ] Щокварталу: аудит доставлюваності (Deliverability Hub у Klaviyo), DMARC-звіти, чистка неактивних
